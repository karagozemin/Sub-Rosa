What was delivered

Public receipt surface

The PublishedAuctionEvidence SDK model pairs a canonical Core v2 receipt with transaction evidence. Offline verification checks the receipt, Auction/Settled state, bidder minimum, lifecycle hashes, and atomic settlement/refund relationship.

The receipt page reads the current round from Stellar RPC and compares status, mode, bidder count, winner, and winning amount with the published evidence.

Reusable integration template

The template uses native testnet XLM escrow and the public @sub-rosa/sdk surface. It creates the round, submits three time-locked bids, fetches the Drand beacon, opens and reveals, clears, settles, and writes verified public JSON.

Lifecycle summary

  1. Seller escrows the lot and fixes identical 25 XLM bidder escrow.
  2. Three allowlisted testnet accounts submit encrypted commitment-bound bids.
  3. Amounts remain hidden until Drand round 31393417.
  4. After reveal, the contract records valid bid amounts and clears the highest valid bid.
  5. One atomic settlement call pays, refunds all escrow balances, and transfers the lot.
  6. The SDK exports a canonical receipt; the public page verifies it offline and reconciles live state.

Known limits and scope boundary

  • Testnet only; no real-value or mainnet claim is made.
  • The auction lot is a test asset; bidder escrow is native testnet XLM.
  • The keeper/runner is demo-grade, not highly available production infrastructure.
  • No third-party security audit, production database, multi-tenant dashboard, anti-sybil layer, custom wallet, governance, or fee market is claimed.

SCF separation: Rounds #21-23 and this integration kit were completed as Instawards baseline work before the SCF award. They are not represented as SCF-funded rounds and do not count toward any post-award SCF usage target.
